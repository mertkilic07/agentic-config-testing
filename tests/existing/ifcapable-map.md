# Existing SQLite tests per option (`ifcapable` map, SQLite 3.46.1)

Generated by `scripts/map_ifcapable.py` (static scan of the test sources; nothing was executed). Raw data per file and per guard: `ifcapable-map.json`.

Scanned: 1415 `*.test` files under `test/` and `ext/`; 1313 of them belong to the `quick` suite (rebuilt from `test/permutations.test`; the list was checked to be identical to the output of SQLite's own `test_set` Tcl code run in `tclsh`, but **not checked against a quick-run log**). `ext/jni/src/tests/*.test` (SQL scripts for the Java binding) are not Tcl tests and are left out.

## How to read the table

- **Keyword**: the `::sqlite_options` entry set by `src/test_config.c` for the option. `ifcapable EXPR` (`test/tester.tcl:1745`) runs code only if EXPR is true.
- **Inverted**: for `OMIT_*` and `LIKE_DOESNT_MATCH_BLOBS` the keyword is 1 when the option is *off*. Columns below are written in terms of the **option**, not the keyword.
- **File needs option on / off**: the whole rest of the file is skipped unless the option is on / off (`ifcapable !x {finish_test; return}` or a `return_if_no_*` helper).
- **Blocks need on / off**: individual blocks of tests guarded by the option.
- Counts are numbers of *files*; one file can be in several columns. Numbers in parentheses: all scanned files, including those not in `quick`.

## Limits of this map

- Static text scan: it finds `ifcapable` and `capable` as written; guards computed at run time, `if {[permutation]==...}` checks and checks inside helper `.tcl` files other than the `return_if_no_*` procs are not counted.
- A guard says which tests are *skipped*; it does not prove that the remaining tests exercise the option, nor that unguarded tests are independent of it.
- The quick-suite list is rebuilt from the source text, assuming a unix platform and no `QUICKTEST_INCLUDE`/`QUICKTEST_OMIT`; not verified against a run log.
